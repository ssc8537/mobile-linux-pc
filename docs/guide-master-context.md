## 1. 这个项目是什么

上游开源项目：`https://github.com/Cateners/tiny_container`
一个安卓 App（Kotlin，包名 `com.fct.tc4`），在手机上用 PRoot 跑 Debian 13 + XFCE，
通过内嵌的 **AVNC**（VNC 客户端库）把 Linux 桌面显示出来。

- 系统镜像 = Debian 13.6 (trixie) + XFCE 4.20.4 + Firefox ESR 140.13，约 1147 个包
- 镜像以资产形式内置在 APK 的 `assets/rootfs.tar.zst`，首次启动自动导入，**不联网下载**
- App 首次进入图形界面时会 **新建一个全新的 VNC 配置（ID=0）**，不落库、不持久化

用户（项目所有者）不是程序员，他的表达方式是「我想要什么效果」，需要你把需求翻译成代码。
他自己无法调试，只能靠装 APK 试用后反馈现象。

## 2. 用户明确说过的偏好（务必遵守）

1. **界面要粉色系**（淡粉、能看清、要漂亮），这是他的审美基准。
2. **要 Windows 的使用习惯**，不喜欢 Linux 原生那套。鼠标、任务栏、快捷键都按 Windows 来。
3. **讨厌误触**。绝对不要用「双击」当任何功能的触发方式（会误开应用）。
4. **必须有回退版本**。每次交付 APK 都要进版本归档，出错能退回上一版。
5. **文档用中文写**（`.md` 不影响代码，他看得懂中文文档）。
6. **交付要能直接装**：APK 必须已签名，且所有版本用同一把证书，能互相覆盖安装。
7. **不要自作主张加功能**。清单里没提到的默认按他说的做；拿不准就先问，不要直接写。
8. **先探讨再动手**。大功能要先给他方案和取舍，他确认后才写代码。
9. **不要往 GitHub 推送**，除非他明确下命令说「上传」。这一点最容易被违反，注意。
10. 他的手机：iQOO Neo 10，骁龙 8 Gen 3。也提到想在一体机（无键盘鼠标的触摸大屏）上用。

## 3. 文件命名规则（用户硬性要求）

- **全部英文**，不要中文目录名 / 文件名。
- 目录名格式：`<5 个字母的专业前缀>-<一眼能看懂的解释>-<权限标记>`
  - 例：`build-env-toolchain`、`refs-reference-assets-deletable`
- 权限标记只有两种：
  - `-deletable`（可删除，一次性工具、缓存、中间产物）
  - `-keep-forever`（永久保留，交付物、文档、签名密钥）
- 唯一例外：用户自己创建的 `黑客键盘-优秀案例2`，其命名规则由他本人定义
  （源码叫「优秀案例1」，第二个源码叫「优秀案例2」），不要改名。

## 4. 交接文档为什么拆成多篇

用户担心文档太长 AI 会「幻觉」。经验上单个 Markdown 文件在 **3000 汉字以内**时
事实保持率稳定，超过后细节开始漂移。所以本项目约定：

- 每篇文档 **≤ 2500 汉字**（约 3000 的安全上限的 85%）
- 宁可多分几篇，也不要把所有内容塞进一篇
- 每篇开头写清「这篇解决什么问题」，结尾写清「下一篇该读哪个」

> 说明：这是一个保守的工程经验值，不是严格基准测试结果。写新文档时沿用即可。
